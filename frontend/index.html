Pipeline Architecture & Flow

1

Ingestion Layer

Receives CDC JSON stream or batch files. Computes SHA-256 fingerprint hash.

→
2

Validation & Gatekeeper

Validates envelope schema, business rules & referential integrity. Routes failures to DLQ.

→
3

Deduplication & Sequencing

Filters duplicate event IDs. Compares sequence numbers & timestamps for out-of-order mutations.

→
4

Dual-Table Publishing

Upserts authoritative Current-State table & appends to immutable SCD Type 2 History.

Data Dictionary & Schema Conventions

Table Name Grain Primary Key Key Foreign Keys Key Business Rules
dim_customers_current 1 row per customer customer_id None Latest active state. Monotonic sequence protection. Soft-delete flag.
dim_customers_history 1 row per change version history_id pipeline_run_id SCD Type 2. Exact 1 active record (is_current = 1). Preserves out-of-order changes.
fct_orders_current 1 row per order order_id customer_id Referential integrity enforced: customer must exist and be active.
quarantine_records 1 row per rejected event quarantine_id pipeline_run_id Stores raw payload, error code, failure reason. Supports replay/retry.
processed_events 1 row per ingested event event_id pipeline_run_id Idempotency ledger. Prevents duplicate event replay.
pipeline_runs 1 row per execution batch run_id None Observability ledger: start/end timestamps, duration, counts, status.
